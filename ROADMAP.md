# Roadmap

This document tracks planned development milestones. Features should only be marked as complete once implemented and tested.

## Current milestone: v0.1.0-alpha.1

**Goal:** Establish the initial repository baseline.

- [ ] Commit the first dashboard iteration.
- [ ] Add the Google Apps Script backend.
- [ ] Establish project documentation.
- [ ] Establish a consistent repository structure.

## v0.2.0 - Frontend and backend integration

**Goal:** Establish a reliable connection between the dashboard, Apps Script and Google Sheets.

- [ ] Verify the Apps Script deployment and API response.
- [ ] Establish a documented API response structure.
- [ ] Load real portfolio holdings.
- [ ] Load real portfolio summary values.
- [ ] Add meaningful loading, success and error states.
- [ ] Validate calculations against the spreadsheet.

## v0.3.0 - Portfolio functionality

**Goal:** Make the main portfolio dashboard accurate and useful.

- [ ] Holdings and investment breakdown.
- [ ] Buy and sell transaction handling.
- [ ] Dividend tracking.
- [ ] NZD valuation and historical transaction FX.
- [ ] Region, sector and industry allocation.
- [ ] Performance history and charts.
- [ ] Grouped transaction history.

## v0.4.0 - Market data and automation

**Goal:** Improve live data and reduce manual work.

- [ ] NZ, Australian and US market status.
- [ ] Currency exchange rate updates.
- [ ] Automated data refresh.
- [ ] Market and instrument identification.
- [ ] Error handling for missing or delayed market data.

## v0.5.0 - Refinement

**Goal:** Improve reliability and usability.

- [ ] Responsive layouts.
- [ ] Better filtering and sorting.
- [ ] Data validation.
- [ ] Performance improvements.
- [ ] Test edge cases and unusual transactions.

## v1.0.0 - First stable release

**Goal:** Deliver a complete, tested and usable investment tracker.

- [ ] Core features implemented.
- [ ] Portfolio calculations verified.
- [ ] Data persistence and API reliability tested.
- [ ] Documentation completed.
- [ ] No known critical bugs.
- [ ] Deployment and recovery procedures documented.

## Prioritisation

Features should be prioritised in this order:

1. Data correctness and preservation.
2. Backend reliability.
3. Core portfolio functionality.
4. Market data and automation.
5. User interface improvements.

New features should not compromise existing working functionality.
